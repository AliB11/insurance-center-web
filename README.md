# سامانه مراکز طرف قرارداد بیمه

برنامهٔ React/TypeScript راست‌به‌چپ برای دریافت اکسل، جستجو، فیلتر، علاقه‌مندی، خروجی اکسل و انتخاب مسیریاب. بک‌اند ندارد؛ دادهٔ واردشده در IndexedDB همان مرورگر نگهداری می‌شود.

**فهرست مراکز فقط مربوط به استان تهران است** (شهر تهران و شهرهای اطراف)؛ بخش [دامنهٔ داده](#دامنهٔ-داده-همهٔ-مراکز-در-استان-تهران) را ببینید.

> مخزن فعلاً فایل واقعی مراکز ندارد. در نبود دادهٔ ذخیره‌شده یا فایل همراه برنامه، ۱۵۱ مرکز **نمونهٔ نمایشی** در استان تهران (۱۸ محلهٔ شهر تهران و ۱۸ شهر اطراف) نشان داده می‌شود؛ این داده‌ها برای مراجعه معتبر نیستند. مراکز نمونه مختصات تقریبیِ مرکزِ همان محله/شهر (با جابه‌جایی قطعی حداکثر ~۱ تا ۲ کیلومتر) دارند تا جریان مسیریابی قابل دیدن باشد؛ این نقطه‌ها آدرس هیچ مطب یا بیمارستانی نیستند. آدرس‌های نمونه عمداً خیابان‌های هم‌نامِ استان‌ها (بزرگراه کردستان، خیابان قزوین، …) را هم دارند.

## اجرا و بررسی

Node.js 22.12 یا جدیدتر پیشنهاد می‌شود.

```sh
npm ci
npm run dev
```

سرور روی `0.0.0.0:5173` باز می‌شود و میزبان‌های پیش‌نمایش `.e2b.app` را می‌پذیرد. برای دامنهٔ توسعهٔ دیگر، فهرست `allowedHosts` در `vite.config.ts` را صریحاً تغییر دهید؛ آن را بی‌قید باز نکنید.

```sh
npm run check       # TypeScript (برنامه و checks/) + منطق + رگرسیون + تعاملات jsdom
npm run build       # خروجی تک‌فایلی dist/index.html با فونت درون فایل
npm audit
npm run preview    # نسخهٔ build روی پورت 4173
```

`tsconfig.checks.json` پوشهٔ `checks/` را هم type-check می‌کند تا خطای نوع در آزمون‌ها پنهان نماند. یک‌جا اجرا کردن همه‌چیز (با سرور روشن): `npm run check:all`.

CI در `.github/workflows/ci.yml` روی هر push و PR دو کار اجرا می‌کند: (۱) type-check + `npm run check` + `npm run build`، (۲) build، بالا آوردن `vite preview` روی ۴۱۷۳ و اجرای ۳۳ بررسی Chromium با `APP_URL`. نصبی‌های شکست‌خورده به‌صورت artifact نگه داشته می‌شوند.

آزمون مرورگر واقعی، در ترمینال دیگر و با سرور روشن:

```sh
npm run check:browser                              # توسعه، پورت 5173
APP_URL=http://127.0.0.1:4173 npm run check:browser  # نسخهٔ نهایی
```

آزمون مرورگر از Chromium بسته‌بندی‌شده برای Linux استفاده می‌کند؛ روی سایر سیستم‌ها مسیر Chromium نصب‌شده را با `CHROMIUM_PATH` بدهید. خروجی‌ها و تصویر آزمون در `.check/` قرار می‌گیرند و وارد Git نمی‌شوند. این آزمون دادهٔ ساختگی خودش را در یک پروفایل موقت وارد می‌کند و دادهٔ مرورگر کاربر را تغییر نمی‌دهد.

## دامنهٔ داده: همهٔ مراکز در استان تهران

دامنه در `src/lib/scope.ts` تعریف شده است (`DATA_SCOPE = TEHRAN_SCOPE`) و این قواعد را اعمال می‌کند:

- **استان همهٔ مراکز «تهران» است و هرگز از آدرس حدس زده نمی‌شود.** نسخهٔ قبلی استان را از ابتدای آدرس می‌خواند؛ در نتیجه «بزرگراه کردستان» ← کردستان، «خیابان قزوین» ← قزوین، «بزرگراه خلیج فارس» ← فارس، «دفتر مرکزی» ← مرکزی، «شهرک گلستان» ← گلستان و «جادهٔ قدیم قم» ← قم ثبت می‌شد. اگر ستون یا سطر عنوانِ فایل استان دیگری بگوید، «تهران» ثبت و مورد در گزارش واردسازی شمرده می‌شود.
- **شهر:** از ستون «شهر» (با املای یکسان: «اسلام شهر» ← «اسلامشهر»، «شهرری» ← «شهر ری»)؛ اگر نبود، از **ابتدای آدرس** و فقط وقتی صریح باشد (`شهریار، …`، `استان تهران، ورامین، …`، `شهر قدس، …`)؛ وگرنه «تهران». نام خیابان هرگز شهر حساب نمی‌شود (`خیابان شهریار، …` ← تهران). نام‌هایی که در تهران نام خیابان/میدان هم هستند (قدس، دماوند، گلستان، حسن‌آباد، …) فقط با «شهر/شهرستان …» یا پس از «استان تهران،» پذیرفته می‌شوند. شهر صریحِ ابتدای آدرس بر پرکردن خودکار خانهٔ خالی از ردیف بالا مقدم است. شهرِ خارج از فهرست شهرهای استان نگه داشته و در گزارش هشدار داده می‌شود (ممکن است نام محله باشد).
- **تلفن:** به شمارهٔ ثابت ۸ رقمی پیش‌شمارهٔ ۰۲۱ افزوده می‌شود تا «تماس» از تلفن همراه هم کار کند؛ «داخلی ۱۲» و بازهٔ «۶۶۹۲۷۰۰۸-۱۰» حذف می‌شوند (قبلاً به شمارهٔ اشتباه یا نامعتبر تبدیل می‌شدند) و شماره‌های چسبیده جدا می‌شوند. شمارهٔ داخل آدرس فقط اگر کامل باشد یا برچسب «تلفن:» داشته باشد برداشته می‌شود (عدد بی‌برچسب ممکن است پلاک یا کد پستی باشد).
- **دادهٔ ذخیره‌شدهٔ نسخه‌های قبل** هنگام باز شدن برنامه خودکار اصلاح می‌شود (`src/lib/migrate.ts`، نسخهٔ قالب ۲): استان، شهر، تلفن و رشتهٔ جستجو بازسازی و دوباره ذخیره می‌شوند، اعلان کوتاهی نمایش داده می‌شود و یادداشتی در «گزارش داده» ثبت می‌شود. اجرای دوباره تغییری نمی‌دهد. نیازی به حذف داده یا بارگذاری مجدد فایل نیست.
- **جستجو:** نوع معبر اختیاری است؛ «اتوبان کردستان» مراکز «بزرگراه کردستان» را هم پیدا می‌کند و «خیابان ولیعصر» آدرسی را که فقط «ولیعصر، …» دارد. جستجو به تفاوت املاییِ فاصله/نیم‌فاصله/خط تیره هم حساس نیست: «شهرقدس» ← «شهر قدس»، «حسناباد» ← «حسن‌آباد» و «۰۲۱-۶۶۹۲۷۰۰۸» شمارهٔ ذخیره‌شدهٔ `02166927008` را پیدا می‌کند؛ هایلایت همین تطبیق‌ها را پوشش می‌دهد.
- **تبدیل آدرس به مختصات:** جستجوی OSM به محدودهٔ استان تهران محدود است و هر پاسخی بیرون از این محدوده رد می‌شود؛ پس «بزرگراه کردستان» هرگز به سنندج نمی‌رسد.
- **رابط:** «استان تهران» در سربرگ، بنر، چاپ و عنوان صفحه نمایش داده می‌شود. فیلتر بی‌اثر «استان» جای خود را به یک توضیح داده و کاشی «دارای تلفن» جای شمارش استان را گرفته است. برچسب محل تکرار ندارد («تهران» یا «تهران، شهریار»).

برای فهرست سراسری، در `src/lib/scope.ts` مقدار `DATA_SCOPE` را `null` کنید. در آن حالت هم استان فقط از ستون «استان»، سطر عنوان صریح («استان فارس») یا نام شیت خوانده می‌شود و هرگز از آدرس.

## ورود داده

- فرمت‌های دستی: `.xlsx`، `.xls`، `.xlsm` و CSV با UTF-8؛ حداکثر ۲۰ مگابایت.
- ستون‌های پیشنهادی: `نام مرکز`، `شهر`، `آدرس`، `تلفن`، `دسته`، `نوع مرکز`، `latitude`، `longitude`. ستون `استان` اختیاری است (همه «تهران» ثبت می‌شوند). برای دقیق‌ترین شهر، ستون `شهر` را پر کنید.
- ستون مختصات اختیاری است. نام‌های فارسی `عرض جغرافیایی` و `طول جغرافیایی` و نام‌های `lat`، `lng` و `lon` نیز پذیرفته می‌شوند.
- ترتیب مختصات: **عرض، طول** (WGS84). ارقام فارسی و عربی و ممیز `٫` قابل خواندن‌اند. مقدار نامعتبر حذف و در گزارش ثبت می‌شود؛ مختصات از آدرس حدس زده نمی‌شود.
- شیت‌های مخفی، ادغام‌های عمودی، هدر تکراری و سطرهای گروه‌بندی بررسی می‌شوند. تشخیص ساختار اکسل ابتکاری است؛ گزارش واردسازی را با فایل واقعی تطبیق دهید.
- برای دادهٔ همراه برنامه، فایل را در `public/data/centers.xlsx` (یا `centers.csv`) قرار دهید. پوشهٔ `public/` در مخزن وجود ندارد و باید ساخته شود. بارگذار در زمان اجرا این نام‌ها را به‌ترتیب بررسی می‌کند: `data/centers.xlsx`، `centers.xlsx`، `data.xlsx`، `hr.xlsx`، `data/data.xlsx`، `data/centers.xls`، `centers.xls`، `data/centers.csv`، `centers.csv` (فهرست در `src/lib/loader.ts`). دادهٔ ذخیره‌شدهٔ مرورگر اولویت دارد (و با قواعد فعلی خودکار اصلاح می‌شود)؛ برای دیدن فایل جدید، دادهٔ قبلی را حذف کنید؛ برنامه خودش دوباره فایل همراه و سپس دادهٔ نمونه را بررسی می‌کند و لازم نیست صفحه را دستی تازه کنید.
- دریافت آنلاین قابل لغو است: دکمهٔ «لغو دریافت» یا بستن پنجره، درخواست را با `AbortSignal` قطع می‌کند و پاسخ دیررس داده را عوض نمی‌کند.
- سقف‌ها: فایل ۲۰ مگابایت، هر شیت یک میلیون خانه، مجموع شیت‌ها دو میلیون خانه و حداکثر ۶۰ شیت. گزارش (سطرهای کنارگذاشته‌شده و یادداشت‌ها) در ۴۰/۵۰ مورد کوتاه می‌شود و شمار بقیه صریحاً نوشته می‌شود.
- سطرهای عنوانِ دسته («بیمارستان‌ها»، «داروخانه ها»، «مراکز تصویربرداری») مرکز ثبت نمی‌شوند و فقط زمینهٔ دستهٔ ردیف‌های بعدی‌اند؛ نام واقعی مرکزی مثل «داروخانه البرز» همچنان یک ردیف است.
- دریافت آنلاین فقط مستقیم و با HTTP(S) انجام می‌شود و فایل‌های `.xlsx`/`.xls`/`.xlsm`/`.csv` را می‌پذیرد (برای CSV، متن باید جدولی باشد؛ صفحهٔ HTML/JSON به‌جای فایل داده پذیرفته نمی‌شود). اگر مبدأ CORS را مجاز نکند، فایل را دستی دانلود و وارد کنید. برنامه از واسطهٔ عمومی برای دور زدن CORS استفاده نمی‌کند.

## مسیریابی

از دکمهٔ «مسیریابی» کارت، آیکن جدول یا «انتخاب مسیریاب» در جزئیات استفاده کنید:

1. **با مختصات:** نمایش مقصد در نشان وب/اندروید، لینک مسیر با مبدأ (GPS)، لینک نشان آیفون، مسیریابی Waze و Google Maps (نقطه یا مسیر از موقعیت من)، و «کپی لینک نشان» برای ارسال لینک به گوشی. لینک‌ها فقط پارامترهای مستند نشان را می‌سازند.
2. **وسیلهٔ نقلیه:** برای لینک مسیر نشان می‌توانید خودرو (`vehicle=d`) یا موتور (`vehicle=m`) را انتخاب کنید؛ همان مقدار به لینک iOS هم منتقل می‌شود.
3. **مبدأ نشان:** دکمهٔ «استفاده از موقعیت من» درخواست مجوز GPS می‌دهد، مبدأ را به لینک مسیر اضافه می‌کند و فاصلهٔ خط مستقیم مبدأ–مقصد را نشان می‌دهد. درخواست خودکار موقعیت وجود ندارد. در صورت عدم دسترسی، لینک مقصد همچنان کار می‌کند. موقعیت مبدأ ذخیره نمی‌شود.
4. **سنجش مختصات:** هر نقطه پیش از باز شدن در لینک‌ها با چارچوب ایران سنجیده می‌شود. اگر عرض و طول جابه‌جا وارد شده باشند، هشدار داده و دکمهٔ «اصلاح پیشنهادی» همان نقطهٔ جابه‌جا را برعکس می‌کند (فقط در همین پنجره، بدون تغییر فایل). نقاط صفر یا خارج از ایران هم هشدار می‌گیرند؛ لینک بازمی‌ماند چون تشخیص نهایی با کاربر است.
5. **بدون مختصات:** پنجرهٔ «تبدیل آدرس به مختصات» باز می‌شود (پایین همین بخش را ببینید). همچنین جستجوی نام و آدرس در Google Maps و کپی آدرس برای نشان، بلد و سایر برنامه‌ها. لینک متنی ساختگی برای نشان تولید نمی‌شود. ورود دستی نقطهٔ دقیق نیز ممکن است؛ ارقام فارسی، ممیز «٫» و قالب درجه/دقیقه/ثانیه (`35°42′30″`، `S/W`) پذیرفته می‌شود. این نقطه فقط تا بسته‌شدن پنجره باقی می‌ماند.
6. **آیفون:** لینک `neshan://` نیاز به نصب برنامه دارد و در سربرگ جدا باز می‌شود تا اگر برنامه نبود، پنجرهٔ برنامه خراب نشود؛ لینک وب جداگانه نیز موجود است. بازشدن اپ وابسته به سیستم‌عامل، مرورگر و تنظیمات کاربر است.

قالب‌های نشان مطابق [مستندات رسمی نشان، پرسش‌های متداول](https://platform.neshan.org/):

```text
https://nshn.ir/?lat=LAT&lng=LNG
https://nshn.ir/?origin=LAT,LNG&destination=LAT,LNG&vehicle=d|m
neshan://?ll=LAT,LNG
neshan://?origin=LAT,LNG&destination=LAT,LNG&vehicle=…   (iOS: d,b,p,m,w)
```

تست‌های رگرسیون همین قالب‌ها را قفل کرده‌اند؛ اگر نشان فردا قالب را عوض کرد، ابتدا `checks/regression-check.ts` را با مستندات تازه مقایسه و سپس تابع را ویرایش کنید.

### اگر فقط آدرس متنی داریم: تبدیل آدرس به مختصات در پنجرهٔ مسیریابی

برای مراکز بدون مختصات، دکمه‌های «جستجو با سرویس نشان» و «جستجو با نقشهٔ آزاد OSM (بدون کلید)» نام و آدرس را به سرویس می‌دهند و **کاندید** می‌گیرند؛ هیچ نتیجه‌ای خودکار مقصد قرار نمی‌گیرد:

- پاسخ‌ها غربال می‌شوند: باید مختصات معتبر و داخل چارچوب ایران و **داخل محدودهٔ استان تهران** باشد، نام استان/شهر پاسخ با مرکز هم‌خوان باشد، و اگر همان شهر در فایل، مرکزِ دارای مختصات دیگری دارد، پاسخ نباید از آن‌ها دور باشد (بیش از ۳۰ کیلومتر = رد؛ ۱۲ تا ۳۰ = هشدار). نام شهر پاسخ با فهرست شهرهای استان سنجیده می‌شود؛ برچسبی مثل «تهران، ورامین» برای مرکز شهر «تهران» تطبیق حساب نمی‌شود (پیش‌تر فقط وجود نام استان در برچسب کافی بود). این قانون همان تلهٔ کلاسیک «خیابان کمیلِ ساری به‌جای تهران» را می‌گیرد.
- با کلید نشان، از وب‌سرویس رسمی `https://api.neshan.org/geocoding/v1` (هدر `Api-Key`) استفاده می‌شود و `unMatchedTerm` پاسخ نمایش داده می‌شود تا بفهمید چه بخشی از آدرس تطبیق نخورده است.
- کلید وب‌سرویس **اختیاری** است، فقط با کلیک شما در حافظهٔ همین مرورگر ذخیره می‌شود و فقط به `api.neshan.org` ارسال می‌شود. برای دادهٔ حساس یا حجم بالا، همچنان راه درست، **ژئوکدینگ دسته‌ای در سمت سرور** (کلید محرمانه، تأیید انسانی موارد مبهم، ثبت مختصات تأییدشده در فایل) است؛ جستجوی عمومی پاسخ قطعی مقصد بیمار نیست.
- جستجو فقط با کلیک انجام می‌شود، با مهلت ۱۲ ثانیه، سقف حجم پاسخ و محدودیت `countrycodes=ir` و `viewbox` استان تهران (`bounded=1`) برای OSM. بستن پنجره یا جستجوی دوباره، درخواست باز را لغو می‌کند. پایان مهلت پیام روشن می‌دهد و اسپینر متوقف می‌شود.

## دادهٔ ذخیره‌شده، علاقه‌مندی‌ها و حذف

- داده در IndexedDB همین مرورگر می‌ماند. اگر خواندن آن ناموفق باشد یا قالبش قابل بازیابی نباشد، برنامه **روی آن نمی‌نویسد**؛ پیام می‌دهد که دادهٔ قبلی قابل خواندن نبود و پاک نشد، سپس فایل همراه/دادهٔ نمونه را نشان می‌دهد. دادهٔ ناقص (مثلاً قالب قدیمی که یک فیلد مشتق‌شده را ندارد) خودکار بازسازی و دوباره ذخیره می‌شود.
- «حذف دادهٔ ذخیره‌شده» پس از موفقیت، مسیر بارگذاری اولیه را دوباره اجرا می‌کند؛ بنابراین به صفحهٔ «فایلی بارگذاری نشد» نمی‌رسید.
- علاقه‌مندی‌ها با کلید نسخه‌دار `sepah-favs-v2` و **به‌ازای هر مجموعهٔ داده** (منبع + نام فایل) ذخیره می‌شوند؛ علاقه‌مندی‌های یک فایل روی فایل بعدی نمی‌نشیند و کلید قدیمی `sepah-favs` یک‌بار به قالب تازه منتقل می‌شود. کلید نشان (`sepah-neshan-key`) و جستجوهای اخیر (`sepah-recent`) جدا و در `localStorage` می‌مانند و با حذف داده پاک نمی‌شوند.
- چاپ: بخش بنر در چاپ پنهان می‌شود و نتایج تمام عرض صفحه را می‌گیرند (آزمون مرورگر همین را می‌سنجد). جدول نتایج در چاپ بدون اسکرول افقی چاپ می‌شود.

## وابستگی و امنیت

- `xlsx` قدیمی npm در نسخهٔ 0.18.5 باقی مانده و هشدارهای امنیتی داشت. alias قفل‌شدهٔ `npm:@e965/xlsx@0.20.3` جایگزین آن شده است؛ این **بازنشر شخص ثالث SheetJS** است، نه بستهٔ رسمی منتشرشده توسط SheetJS روی npm. برای محیط با الزامات زنجیرهٔ تأمین، نسخهٔ تأییدشده را از رجیستری داخلی سازمان تأمین کنید.
- افزونهٔ singlefile و زنجیرهٔ وابستگی آسیب‌پذیر آن حذف شده است. افزونهٔ کوچک `checks/single-file-plugin.ts` فقط JS/CSS خروجی همین ورودی HTML را درون فایل قرار می‌دهد و در صورت باقی‌ماندن chunk خطا می‌دهد.
- فونت محلی است؛ نمایش رابط نیاز به CDN ندارد. API نقشه، لینک مسیریاب و دریافت فایل آنلاین همچنان به شبکه نیاز دارند.
- سقف حجم و ابعاد شیت، جایگزین sandbox کامل فایل ناشناخته نیست. برای فایل‌های بسیار بزرگ یا منابع نامطمئن، پردازش در Worker با سقف زمان/حافظه یا سرویس ایزولهٔ سمت سرور پیشنهاد می‌شود.
